OpenCode Desktop lists the plugins that run in its interface under **Settings > Plugins**. The page shows the built-in plugins that ship with the app and the GUI parts of your [plugins](/plugins#desktop).

| Source | Where it comes from | Label | How to remove it |
| --- | --- | --- | --- |
| Built-in | Ships with the app | **Built-in** | Cannot be removed; turn it off |
| Plugin | A plugin in `opencode.json(c)` that exports `./gui` | — | Remove the plugin from `opencode.json(c)` |

Built-in plugins provide the app's workspace features, such as the [terminal](/desktop/terminal), [review](/desktop/review) panel, and [browser](/desktop/browser). They are enabled by default.

## Open Settings > Plugins

Open **Settings** (**Cmd+,** on macOS or **Ctrl+,** on Windows and Linux) and select **Plugins** in the left navigation bar.

```text
/settings?tab=plugins
```

You can also open the command palette (**Cmd+K** / **Ctrl+K**), search for `Plugins`, and jump directly to the page.

<Callout type="note">
The app-level **Plugins** page lists the plugins that run in this desktop app's interface. Each server's **Extensions** tab lists [MCP servers](/mcp-servers), server [plugins](/plugins), and [skills](/skills) on that server.
</Callout>

## Enable, disable, and reload

Every row in **Settings > Plugins** shows the plugin's ID, its current status, a **Reload** button, and an enable switch. Built-in rows also carry a **Built-in** label; rows from installed plugins have no label.

```text
terminal  Built-in   Active    Reload  [on]
acme                 Active    Reload  [on]
```

| Control | Behavior |
| --- | --- |
| **Switch** | Enables or disables the plugin across all desktop windows. The preference persists in the desktop database across restarts. |
| **Reload** | Reloads both the window entry and the main-process entry and clears any recorded failure. If a main-process reload fails, the last working revision remains active. |

When you disable a plugin, the host immediately withdraws all of its commands, panels, slots, titlebar items, native menu items, and settings pages in a single frame.

If the desktop app no longer knows a plugin's ID, for example because the plugin was just removed, its switch and **Reload** button show a **Plugin not found** error.

## Add plugins

Third-party GUI plugins come from [plugins](/plugins) in your configuration. A plugin package that exports `./gui` adds its GUI to the app; there is no separate install step. Add the plugin to your global configuration:

```jsonc title="~/.config/opencode/opencode.jsonc"
{
  "plugins": ["opencode-acme"],
}
```

The plugin appears in **Settings > Plugins** without a label. Configure the plugin globally to make its GUI available in every window.

### Where GUI plugins load

OpenCode Desktop loads GUI plugins only from plugins on its own background server. The web app, and plugins on other connected servers such as [SSH](/desktop/ssh), [WSL](/desktop/wsl), and HTTP servers, do not add their GUI to the app yet; those plugins still run on their server.

### Remove a plugin

Turn the plugin off with its switch, or remove it from `opencode.json(c)`. For a global package plugin, you can also use the CLI:

```sh
opencode plugin remove opencode-acme
```

<Callout type="note">
A plugin's GUI uses the plugin's ID. If a built-in plugin already uses that ID, the built-in plugin loads and the plugin's GUI does not.
</Callout>

## Plugin statuses

Each plugin reports its live state in the current window:

| Status | Meaning |
| --- | --- |
| **Active** | The plugin's setup completed and its contributions are live. |
| **Loading** | The plugin is loading its bundle or waiting for its global stores or hard dependencies. |
| **Disabled** | The plugin is turned off in Settings. |
| **Blocked** | A hard dependency (`requires`) that this plugin depends on is disabled, failed, or itself blocked. Re-enabling the provider automatically resumes the plugin. |
| **Failed** | The plugin's bundle failed to load, its setup threw an error, or one of its reactive effects crashed. |

If a plugin fails during setup or while rendering a contribution, the error stack is displayed in red directly below its status in **Settings > Plugins**. One broken plugin never blocks the rest of the application.

All 13 built-in plugins are enabled by default. `wsl` runs on Windows only; all other built-ins run on macOS, Windows, and Linux.

| ID | Feature area | Dependencies (`uses`) |

| `context` | Context usage ring, token breakdown tab, and session JSON export | — |
| `btw` | `/btw` side-question slash command and answer tabs | — |

| `terminal` | Dock terminal tabs powered by `ghostty-web` | — |
| `file` | Workspace file tree, artifact viewers, link handler, and desktop **Open in** menu | `review.changes`, `browser` |

| `details` | Session header summary popover, worktree mover, and server status popovers | `review.changes` |
| `browser` | Native Chromium browser pane, element comment picker, and `browser.*` agent tools | `browser.pane` (main IPC) |

## Customizing plugin shortcuts

Commands contributed by active plugins appear in **Settings > Shortcuts** alongside core commands.

1. Open **Settings > Shortcuts** and use the **Search shortcuts** box to find the command.
2. Click the shortcut button (or **Unassigned**) so it reads **Press keys**.
3. Press the desired key combination to save it under the published command ID (such as `terminal.toggle` or `debug.toggle`).
4. Press **Backspace** or **Delete** while recording to clear a binding, or **Escape** to cancel.
