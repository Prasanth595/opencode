OpenCode sử dụng [AI SDK](https://ai-sdk.dev/) và [Models.dev](https://models.dev) để hỗ trợ **hơn 75 nhà cung cấp LLM** và hỗ trợ chạy mô hình cục bộ.

Để thêm một nhà cung cấp, bạn cần:

1. Thêm khóa API của nhà cung cấp bằng lệnh `/connect`.
2. Cấu hình nhà cung cấp trong cấu hình OpenCode của bạn.

---

### Thông tin đăng nhập

Khi bạn thêm khóa API của nhà cung cấp bằng lệnh `/connect`, chúng được lưu
trong `~/.local/share/opencode/auth.json`.

---

### Cấu hình

Bạn có thể tùy chỉnh các nhà cung cấp thông qua mục `provider` trong cấu hình
OpenCode của bạn.

---

#### Base URL

Bạn có thể tùy chỉnh base URL cho bất kỳ nhà cung cấp nào bằng cách đặt tùy chọn `baseURL`. Điều này hữu ích khi bạn dùng dịch vụ proxy hoặc endpoint tùy chỉnh.

```json title="opencode.json" {6}
{
  "$schema": "https://opencode.ai/config.json",
  "provider": {
    "anthropic": {
      "options": {
        "baseURL": "https://api.anthropic.com/v1"
      }
    }
  }
}
```

---

#### Ẩn mô hình

Bạn có thể ẩn các mô hình cụ thể khỏi bộ chọn `/models` của một nhà cung cấp bằng tùy chọn `blacklist`. Điều này hữu ích khi nhà cung cấp cung cấp những mô hình bạn không muốn dùng hoặc chọn.

```json title="opencode.json" {6}
{
  "$schema": "https://opencode.ai/config.json",
  "provider": {
    "anthropic": {
      "blacklist": ["claude-opus-4-20250514"]
    }
  }
}
```

Tùy chọn ngược lại là `whitelist`, ẩn mọi mô hình ngoại trừ những mô hình được liệt kê.

```json title="opencode.json" {6}
{
  "$schema": "https://opencode.ai/config.json",
  "provider": {
    "anthropic": {
      "whitelist": ["claude-sonnet-4-20250514"]
    }
  }
}
```

Cả hai tùy chọn đều nhận một mảng ID mô hình — chính là các ID hiển thị trong bộ chọn `/models`.

- `blacklist` loại bỏ các mô hình được liệt kê khỏi bộ chọn.
- `whitelist` chỉ giữ lại các mô hình được liệt kê và ẩn phần còn lại.
- Bạn có thể kết hợp cả hai: `whitelist` thu hẹp tập mô hình, rồi `blacklist` loại bỏ các mục khỏi đó.

## OpenCode Zen

OpenCode Zen là danh sách các mô hình do đội ngũ OpenCode cung cấp, đã được
kiểm thử và xác minh là hoạt động tốt với OpenCode. [Tìm hiểu thêm](https://opencode.ai/v2/docs/console/).

:::tip
Nếu bạn mới bắt đầu, chúng tôi khuyên bạn nên bắt đầu với OpenCode Zen.
:::

1. Chạy lệnh `/connect` trong TUI, chọn `OpenCode Zen`, rồi truy cập [opencode.ai/auth](https://opencode.ai/zen).

   ```txt
   /connect
   ```

2. Đăng nhập, thêm thông tin thanh toán và sao chép khóa API của bạn.

3. Dán khóa API của bạn.

   ```txt
   ┌ API key
   │
   │
   └ enter
   ```

4. Chạy `/models` trong TUI để xem danh sách mô hình chúng tôi khuyến nghị.

   ```txt
   /models
   ```

Nó hoạt động giống như mọi nhà cung cấp khác trong OpenCode và hoàn toàn tùy chọn khi sử dụng.

### Amazon Bedrock

Để dùng Amazon Bedrock với OpenCode:

1. Truy cập **Model catalog** trong bảng điều khiển Amazon Bedrock và yêu cầu
   quyền truy cập các mô hình bạn muốn dùng.

   :::tip
   Bạn cần có quyền truy cập mô hình bạn muốn dùng trong Amazon Bedrock.
   :::

2. **Cấu hình xác thực** bằng một trong các phương pháp sau:

   ***

   #### Biến môi trường (Khởi động nhanh)

   Đặt một trong các biến môi trường sau khi chạy opencode:

   ```bash
   # Option 1: Using AWS access keys
   AWS_ACCESS_KEY_ID=XXX AWS_SECRET_ACCESS_KEY=YYY opencode

   # Option 2: Using named AWS profile
   AWS_PROFILE=my-profile opencode

   # Option 3: Using Bedrock bearer token
   AWS_BEARER_TOKEN_BEDROCK=XXX opencode
   ```

   Hoặc thêm chúng vào bash profile của bạn:

   ```bash title="~/.bash_profile"
   export AWS_PROFILE=my-dev-profile
   export AWS_REGION=us-east-1
   ```

   ***

   #### Tệp cấu hình (Khuyến nghị)

   Để cấu hình riêng cho từng dự án hoặc cấu hình lâu dài, hãy dùng `opencode.json`:

   ```json title="opencode.json"
   {
     "$schema": "https://opencode.ai/config.json",
     "provider": {
       "amazon-bedrock": {
         "options": {
           "region": "us-east-1",
           "profile": "my-aws-profile"
         }
       }
     }
   }
   ```

   **Các tùy chọn khả dụng:**
   - `region` - Khu vực AWS (ví dụ: `us-east-1`, `eu-west-1`)
   - `profile` - Hồ sơ AWS có tên trong `~/.aws/credentials`
   - `endpoint` - URL endpoint tùy chỉnh cho VPC endpoint (bí danh của tùy chọn `baseURL` chung)

   :::tip
   Các tùy chọn trong tệp cấu hình được ưu tiên hơn biến môi trường.
   :::

   ***

   #### Nâng cao: VPC Endpoint

   Nếu bạn dùng VPC endpoint cho Bedrock:

   ```json title="opencode.json"
   {
     "$schema": "https://opencode.ai/config.json",
     "provider": {
       "amazon-bedrock": {
         "options": {
           "region": "us-east-1",
           "profile": "production",
           "endpoint": "https://bedrock-runtime.us-east-1.vpce-xxxxx.amazonaws.com"
         }
       }
     }
   }
   ```

   :::note
   Tùy chọn `endpoint` là bí danh của tùy chọn `baseURL` chung, dùng thuật ngữ riêng của AWS. Nếu cả `endpoint` và `baseURL` đều được chỉ định thì `endpoint` được ưu tiên.
   :::

   ***

   #### Phương pháp xác thực
   - **`AWS_ACCESS_KEY_ID` / `AWS_SECRET_ACCESS_KEY`**: Tạo một người dùng IAM và tạo access key trong AWS Console
   - **`AWS_PROFILE`**: Dùng các hồ sơ có tên trong `~/.aws/credentials`. Trước tiên hãy cấu hình bằng `aws configure --profile my-profile` hoặc `aws sso login`
   - **`AWS_BEARER_TOKEN_BEDROCK`**: Tạo khóa API dài hạn từ bảng điều khiển Amazon Bedrock
   - **`AWS_WEB_IDENTITY_TOKEN_FILE` / `AWS_ROLE_ARN`**: Dành cho EKS IRSA (IAM Roles for Service Accounts) hoặc các môi trường Kubernetes khác có liên kết danh tính OIDC. Kubernetes tự động tiêm các biến môi trường này khi dùng service account annotations.

   ***

   #### Thứ tự ưu tiên xác thực

   Amazon Bedrock sử dụng thứ tự ưu tiên xác thực sau:
   1. **Bearer Token** - Biến môi trường `AWS_BEARER_TOKEN_BEDROCK` hoặc token từ lệnh `/connect`
   2. **AWS Credential Chain** - Hồ sơ, access key, thông tin đăng nhập dùng chung, vai trò IAM, Web Identity Token (EKS IRSA), metadata của instance

   :::note
   Khi bearer token đã được đặt (qua `/connect` hoặc `AWS_BEARER_TOKEN_BEDROCK`), nó được ưu tiên hơn mọi phương pháp thông tin đăng nhập của AWS, bao gồm cả các hồ sơ đã cấu hình.
   :::

3. Chạy lệnh `/models` để chọn mô hình bạn muốn.

   ```txt
   /models
   ```

:::note
Với các inference profile tùy chỉnh, hãy dùng tên mô hình và tên nhà cung cấp trong khóa và đặt thuộc tính `id` thành arn. Điều này đảm bảo việc lưu cache hoạt động đúng.
:::

```json title="opencode.json"
{
  "$schema": "https://opencode.ai/config.json",
  "provider": {
    "amazon-bedrock": {
      // ...
      "models": {
        "anthropic-claude-sonnet-4.5": {
          "id": "arn:aws:bedrock:us-east-1:xxx:application-inference-profile/yyy"
        }
      }
    }
  }
}
```

### Atomic Chat

Bạn có thể cấu hình opencode để dùng mô hình cục bộ thông qua [Atomic Chat](https://atomic.chat), một ứng dụng desktop chạy LLM cục bộ sau một máy chủ API tương thích OpenAI (endpoint mặc định `http://127.0.0.1:1337/v1`).

```json title="opencode.json" "atomic-chat" {5, 6, 8, 10-14}
{
  "$schema": "https://opencode.ai/config.json",
  "provider": {
    "atomic-chat": {
      "npm": "@ai-sdk/openai-compatible",
      "name": "Atomic Chat (local)",
      "options": {
        "baseURL": "http://127.0.0.1:1337/v1"
      },
      "models": {
        "<your-model-id>": {
          "name": "<your-model-name>"
        }
      }
    }
  }
}
```

Trong ví dụ này:

- `atomic-chat` là ID nhà cung cấp tùy chỉnh. Bạn có thể dùng bất kỳ chuỗi nào bạn muốn.
- `npm` xác định package dùng cho nhà cung cấp này. Ở đây, `@ai-sdk/openai-compatible` được dùng cho mọi API tương thích OpenAI.
- `name` là tên hiển thị của nhà cung cấp trong UI.
- `options.baseURL` là endpoint của máy chủ cục bộ. Hãy đổi host và port cho khớp với cấu hình Atomic Chat của bạn.
- `models` là ánh xạ từ ID mô hình sang tên hiển thị của chúng. Mỗi ID phải khớp với `id` được trả về từ `GET /v1/models` — chạy `curl http://127.0.0.1:1337/v1/models` để liệt kê các id hiện đang được nạp trong Atomic Chat.

:::tip
Nếu các lệnh gọi tool không hoạt động tốt, hãy chọn một mô hình đã nạp có khả năng gọi tool mạnh (ví dụ là biến thể Qwen-Coder hoặc DeepSeek-Coder).
:::

#### Microsoft Entra ID (Azure CLI)

Bạn có thể dùng phiên đăng nhập Azure CLI thay cho khóa API. [Cài đặt Azure CLI](https://learn.microsoft.com/en-us/cli/azure/install-azure-cli), chạy `az login`, rồi chạy `/connect`, chọn **Azure** và chọn **Microsoft Entra ID (Azure CLI)**. Nhập tên Azure Resource khi được yêu cầu. Dùng `az login --tenant TENANT_ID` nếu Resource thuộc về một tenant khác.

Bạn có thể tìm tên Resource bằng cách mở tài nguyên Azure OpenAI hoặc Foundry của mình trong [Azure portal](https://portal.azure.com/) hoặc [Microsoft Foundry](https://ai.azure.com/). Đó cũng chính là phần đầu tiên của endpoint: `my-models` trong `https://my-models.openai.azure.com/` hoặc `https://my-models.services.ai.azure.com/`. Nếu danh tính của bạn có thể liệt kê Resource, bạn cũng có thể tìm tên và Resource group của chúng bằng:

```bash
az cognitiveservices account list \
  --query "[].{name:name,resourceGroup:resourceGroup}" \
  --output table
```

OpenCode không truy vấn các API quản lý của Azure cũng không tự phát hiện bản triển khai. Hãy chọn một mô hình có tên trong danh mục khớp với bản triển khai của bạn, hoặc cấu hình rõ tên triển khai:

```json title="opencode.json"
{
  "$schema": "https://opencode.ai/config.json",
  "provider": {
    "azure": {
      "models": {
        "gpt-5-mini": {
          "id": "gpt-production"
        }
      }
    }
  }
}
```

Hãy gán cho danh tính của bạn vai trò suy luận mà bản triển khai yêu cầu: **Cognitive Services OpenAI User** cho mô hình Azure OpenAI hoặc **Cognitive Services User** cho các mô hình Foundry khác. OpenCode làm mới access token thông qua Azure CLI, kể cả các phiên bản trước 2.54.0, nên bạn chỉ cần đăng nhập lại khi phiên CLI hết hạn.

### Cloudflare AI Gateway

Cloudflare AI Gateway cho phép bạn truy cập các mô hình từ OpenAI, Anthropic, Workers AI và nhiều nguồn khác thông qua một endpoint hợp nhất. Với [Unified Billing](https://developers.cloudflare.com/ai-gateway/features/unified-billing/) bạn không cần khóa API riêng cho từng nhà cung cấp.

1. Truy cập [bảng điều khiển Cloudflare](https://dash.cloudflare.com/), đi đến **AI** > **AI Gateway** và tạo một gateway mới. Ghi lại **Account ID** và **Gateway ID** của bạn.

2. Chạy lệnh `/connect` và tìm kiếm **Cloudflare AI Gateway**.


### DigitalOcean

[Inference Engine](https://docs.digitalocean.com/products/inference/) của DigitalOcean cung cấp quyền truy cập tới các mô hình mở như GPT-OSS, Llama, Qwen và DeepSeek, cùng với các [Inference Router](https://docs.digitalocean.com/products/inference/how-to/use-inference-router/) tùy chỉnh định tuyến từng yêu cầu tới mô hình rẻ nhất, nhanh nhất hoặc phù hợp nhất cho tác vụ.

OpenCode hỗ trợ hai phương pháp xác thực:

- **OAuth (Khuyến nghị)** — Đăng nhập vào tài khoản DigitalOcean của bạn; OpenCode dùng trực tiếp DigitalOcean API token để suy luận và tự phát hiện các Inference Router của bạn.
- **Model Access Key** — Dán một khóa có sẵn từ bảng điều khiển DigitalOcean.

#### OAuth (Khuyến nghị)

1. Chạy lệnh `/connect` và tìm kiếm **DigitalOcean**.

   ```txt
   /connect
   ```

2. Chọn **Login with DigitalOcean**.

   ```txt
   ┌ Select auth method
   │
   │ Login with DigitalOcean
   │ Paste Model Access Key
   └
   ```

3. Trình duyệt của bạn sẽ mở ra để cấp quyền cho OpenCode. Đăng nhập và phê duyệt.

   :::note
   OpenCode yêu cầu các phạm vi OAuth `genai:read` và `inference:query`. DigitalOcean API token của bạn được dùng trực tiếp để suy luận — không có Model Access Key riêng nào được tạo.
   :::

   :::note
   Inference Router chỉ xuất hiện trong bộ chọn mô hình sau khi bạn đăng nhập bằng OAuth. Dán Model Access Key thủ công sẽ không phát hiện được router.
   :::

4. Chạy lệnh `/models`. Các Inference Router của bạn sẽ xuất hiện với định dạng `router:` trong phần chọn mô hình.

   ```txt
   /models
   ```

5. Để lấy các Inference Router mới tạo, hãy chạy lại `/connect` và chọn **DigitalOcean** một lần nữa.

#### Dùng Model Access Key

Nếu bạn muốn dán khóa trực tiếp:

1. Truy cập trang **Manage** trong mục Inference của [bảng điều khiển DigitalOcean](https://cloud.digitalocean.com/) và tạo một khóa mới.

2. Chạy lệnh `/connect` và chọn **DigitalOcean**, rồi **Paste Model Access Key**.

   ```txt
   ┌ Enter your DigitalOcean Model Access Key
   │
   │
   └ enter
   ```

   :::note
   Inference Router không được tự động phát hiện với phương pháp này. Để chúng xuất hiện trong bộ chọn mô hình, hãy đăng nhập bằng OAuth.
   :::

3. Chạy lệnh `/models` để chọn một mô hình.

   ```txt
   /models
   ```

#### Biến môi trường

Ngoài ra, bạn có thể đặt Model Access Key thành biến môi trường.

```bash frame="none"
export DIGITALOCEAN_ACCESS_TOKEN=your-model-access-key
```

#### Inference Router

Inference Router cho phép bạn định nghĩa một chính sách định tuyến trên nhiều mô hình — chọn mô hình rẻ nhất, nhanh nhất hoặc phù hợp nhất cho từng yêu cầu dựa trên tác vụ. Sau khi đăng nhập bằng OAuth, OpenCode hiển thị mỗi router dưới dạng `router:<router-name>` trong bộ chọn mô hình.

Chọn một mô hình router là cách thay thế trực tiếp cho bất kỳ mô hình nào khác — OpenCode chuyển tiếp yêu cầu của bạn và DigitalOcean chọn mô hình nền tảng theo chính sách router của bạn. Tìm hiểu thêm về [Inference Router](https://docs.digitalocean.com/products/inference/how-to/use-inference-router/)

##### Mô hình workflow của GitLab Duo Agent Platform (DAP)

Mô hình workflow của DAP cung cấp một đường thực thi thay thế, định tuyến các
lệnh gọi tool qua Duo Workflow Service (DWS) của GitLab thay vì trò chuyện
agentic tiêu chuẩn. Khi một mô hình `duo-workflow-*` được chọn, OpenCode sẽ:

1. Phát hiện các mô hình khả dụng từ GitLab namespace của bạn
2. Hiển thị bộ chọn nếu có nhiều mô hình khả dụng
3. Lưu mô hình đã chọn xuống đĩa để khởi động nhanh hơn về sau
4. Định tuyến các yêu cầu thực thi tool qua hệ thống tool có kiểm soát quyền của OpenCode

Các mô hình workflow DAP khả dụng tuân theo quy ước đặt tên `duo-workflow-*` và
được phát hiện động từ instance GitLab của bạn.

:::note
Việc phát hiện mô hình workflow chỉ chạy với thông tin đăng nhập được lưu bằng `/connect` (OAuth hoặc
personal access token). Riêng biến môi trường `GITLAB_TOKEN` sẽ không
kích hoạt việc phát hiện.
:::

##### GitLab API Tools (Tùy chọn, nhưng rất khuyến nghị)

Để truy cập các tool của GitLab (merge request, issue, pipeline, CI/CD, v.v.):

```json title="opencode.json"

  "$schema": "https://opencode.ai/config.json",
  "plugin": ["opencode-gitlab-plugin"]
}
```

Plugin này cung cấp năng lực quản lý kho mã nguồn GitLab toàn diện, bao gồm đánh giá MR, theo dõi issue, giám sát pipeline và nhiều hơn nữa.

#### Cấu hình tùy chọn

Nếu bạn thấy một tính năng hoặc mô hình của Helicone chưa được cấu hình tự động trong opencode, bạn luôn có thể tự cấu hình.

Đây là [Model Directory của Helicone](https://helicone.ai/models), bạn cần nó để lấy ID của các mô hình muốn thêm.

```jsonc title="~/.config/opencode/opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "provider": {
    "helicone": {
      "npm": "@ai-sdk/openai-compatible",
      "name": "Helicone",
      "options": {
        "baseURL": "https://ai-gateway.helicone.ai",
      },
      "models": {
        "gpt-4o": {
          // Model ID (from Helicone's model directory page)
          "name": "GPT-4o", // Your own custom name for the model
        },
        "claude-sonnet-4-20250514": {
          "name": "Claude Sonnet 4",
        },
      },
    },
  },
}
```

#### Custom Header

Helicone hỗ trợ header tùy chỉnh cho các tính năng như cache, theo dõi người dùng và quản lý phiên. Thêm chúng vào cấu hình nhà cung cấp của bạn bằng `options.headers`:

```jsonc title="~/.config/opencode/opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "provider": {
    "helicone": {
      "npm": "@ai-sdk/openai-compatible",
      "name": "Helicone",
      "options": {
        "baseURL": "https://ai-gateway.helicone.ai",
        "headers": {
          "Helicone-Cache-Enabled": "true",
          "Helicone-User-Id": "opencode",
        },
      },
    },
  },
}
```

##### Theo dõi phiên

Tính năng [Sessions](https://docs.helicone.ai/features/sessions) của Helicone cho phép bạn gom nhóm các yêu cầu LLM có liên quan. Dùng plugin [opencode-helicone-session](https://github.com/H2Shami/opencode-helicone-session) để tự động ghi lại mỗi cuộc hội thoại OpenCode thành một phiên trong Helicone.

```bash
npm install -g opencode-helicone-session
```

Thêm nó vào cấu hình của bạn.

```json title="opencode.json"
{
  "plugin": ["opencode-helicone-session"]
}
```

Plugin tiêm các header `Helicone-Session-Id` và `Helicone-Session-Name` vào các yêu cầu của bạn. Trong trang Sessions của Helicone, bạn sẽ thấy mỗi cuộc hội thoại OpenCode được liệt kê thành một phiên riêng.

##### Các header Helicone phổ biến

| Header                     | Mô tả                                                              |
| -------------------------- | ------------------------------------------------------------------ |
| `Helicone-Cache-Enabled`   | Bật cache phản hồi (`true`/`false`)                                |
| `Helicone-User-Id`         | Theo dõi số liệu theo người dùng                                   |
| `Helicone-Property-[Name]` | Thêm thuộc tính tùy chỉnh (ví dụ: `Helicone-Property-Environment`) |
| `Helicone-Prompt-Id`       | Liên kết các yêu cầu với phiên bản lời nhắc                        |

Xem [Helicone Header Directory](https://docs.helicone.ai/helicone-headers/header-directory) để biết tất cả header khả dụng.

#### Bản triển khai Poolside

Nếu tổ chức của bạn vận hành một bản triển khai Poolside, hãy cấu hình nó như một nhà cung cấp tùy chỉnh tương thích OpenAI. Lưu khóa API hoặc token do quản trị viên Poolside cấp vào `~/.secrets/poolside-key`. Dùng một ID nhà cung cấp duy nhất và thêm các ID mô hình khả dụng từ bản triển khai của bạn.

```json title="opencode.json"
{
  "$schema": "https://opencode.ai/config.json",
  "provider": {
    "poolside-deployment": {
      "npm": "@ai-sdk/openai-compatible",
      "name": "Poolside deployment",
      "options": {
        "baseURL": "https://poolside.example.com/openai/v1",
        "apiKey": "{file:~/.secrets/poolside-key}"
      },
      "models": {
        "<served-model-id>": {
          "name": "Poolside deployment model",
          "reasoning": true,
          "interleaved": {
            "field": "reasoning_content"
          }
        }
      }
    }
  }
}
```

Hãy thay `poolside.example.com` bằng host của bản triển khai và `<served-model-id>` bằng một ID mô hình được trả về từ endpoint `/openai/v1/models` của nó. Mô hình khả dụng và hành vi suy luận phụ thuộc vào cấu hình của bản triển khai.

:::tip
Bạn cũng có thể cài [Poolside Agent CLI](https://github.com/poolsideai/pool) để dùng tác nhân Poolside ngay trong terminal của mình.
:::

### Snowflake Cortex

[Snowflake Cortex](https://docs.snowflake.com/en/user-guide/snowflake-cortex/cortex-rest-api) cho phép bạn truy cập các mô hình tiên tiến (Claude, OpenAI GPT-5 và nhiều hơn) qua một API tương thích OpenAI. Mọi hoạt động suy luận đều chạy trong phạm vi của Snowflake và được tính phí bằng Snowflake credit. Để biết đơn giá theo từng mô hình, hãy xem [Snowflake Service Consumption Table](https://www.snowflake.com/legal-files/CreditConsumptionTable.pdf).

Bạn chưa có tài khoản Snowflake? [Đăng ký dùng thử miễn phí](https://signup.snowflake.com/?utm_source=opencode&utm_medium=docs&utm_campaign=cortex-provider).

Quy trình lõi của opencode cho việc lập trình, chỉnh sửa tệp và chạy lệnh phụ thuộc vào tool calling. Chỉ các họ Claude và OpenAI trong Snowflake Cortex hỗ trợ điều này. Nhà cung cấp bị giới hạn ở những họ đó nhằm hỗ trợ quy trình lõi.

OpenCode hỗ trợ hai phương pháp xác thực:

- **Browser OAuth (Khuyến nghị)** — đăng nhập bằng IdP/SSO của bạn; không phải quản lý secret, token tự làm mới.
- **Manual bearer token** — dán PAT hoặc JWT từ bảng điều khiển Snowflake.

#### Browser OAuth (Khuyến nghị)

1. Chạy lệnh `/connect` và tìm kiếm **Snowflake Cortex**.

   ```txt
   /connect
   ```

2. Chọn **Login with Snowflake (External Browser)**.

   ```txt
   ┌ Select auth method
   │
   │ Login with Snowflake (External Browser)
   │ Paste PAT or bearer token manually
   └
   ```

3. Nhập [account identifier](https://docs.snowflake.com/en/user-guide/admin-account-identifier) của bạn khi được yêu cầu, ví dụ `myorg-myaccount` hoặc `xy12345.us-east-1`.

   ```txt
   ┌ Snowflake Account Identifier
   │
   │
   └ enter
   ```

4. Tùy chọn nhập một Snowflake role để giới hạn phạm vi phiên (ví dụ `SYSADMIN`). Để trống để dùng role mặc định của bạn.

5. Hoàn tất đăng nhập trong trình duyệt mở ra. OpenCode tự động thu callback OAuth và lưu token — không cần sao chép/dán.

6. Chạy lệnh `/models` để chọn một mô hình.

   ```txt
   /models
   ```

:::note
Browser OAuth dùng tích hợp bảo mật `SNOWFLAKE$LOCAL_APPLICATION` tích hợp sẵn của Snowflake ([tài liệu](https://docs.snowflake.com/en/user-guide/oauth-local-applications)), đang được triển khai dần cho mọi tài khoản. Để kiểm tra tính khả dụng trong tài khoản của bạn:

```sql
SHOW SECURITY INTEGRATIONS LIKE 'SNOWFLAKE$LOCAL_APPLICATION';
```

Nếu kết quả trống, hãy dùng phương pháp **Manual bearer token** bên dưới trong khi tích hợp này được triển khai tới tài khoản của bạn.
:::

#### Manual bearer token

Nếu bạn muốn dán token trực tiếp, hoặc nếu `SNOWFLAKE$LOCAL_APPLICATION` chưa khả dụng trong tài khoản của bạn:

1. Tạo một [Programmatic Access Token (PAT)](https://docs.snowflake.com/en/user-guide/programmatic-access-tokens) trong tài khoản Snowflake của bạn.

2. Chạy lệnh `/connect`, tìm kiếm **Snowflake Cortex** và chọn **Paste PAT or bearer token manually**.

3. Nhập [account identifier](https://docs.snowflake.com/en/user-guide/admin-account-identifier) của bạn khi được yêu cầu.

4. Dán PAT của bạn.

5. Chạy lệnh `/models` để chọn một mô hình.

   ```txt
   /models
   ```

#### Biến môi trường

Với CI hoặc môi trường không có giao diện, hãy đặt PAT hoặc JWT trước khi khởi động opencode:

```bash
export SNOWFLAKE_ACCOUNT=myorg-myaccount
export SNOWFLAKE_CORTEX_TOKEN=your-pat-or-jwt
```

:::note
`SNOWFLAKE_CORTEX_TOKEN` chỉ chấp nhận PAT hoặc JWT — luồng Browser OAuth chỉ khả dụng qua `/connect` và không thể cấu hình bằng biến môi trường. `SNOWFLAKE_CORTEX_PAT` vẫn được hỗ trợ để tương thích ngược.
:::

Danh mục mô hình được cung cấp tự động. Chỉ cần một `opencode.json` tối giản:

```json title="opencode.json"
{
  "$schema": "https://opencode.ai/config.json",
  "model": "snowflake-cortex/claude-sonnet-4-6",
  "small_model": "snowflake-cortex/claude-haiku-4-5"
}
```

## Nhà cung cấp tùy chỉnh

Để thêm bất kỳ nhà cung cấp **tương thích OpenAI** nào không có trong lệnh `/connect`:

:::tip
Bạn có thể dùng mọi nhà cung cấp tương thích OpenAI với opencode. Hầu hết nhà cung cấp AI hiện đại đều cung cấp API tương thích OpenAI.
:::

1. Chạy lệnh `/connect` và cuộn xuống **Other**.

   ```bash
   $ /connect

   ┌  Add credential
   │
   ◆  Select provider
   │  ...
   │  ● Other
   └
   ```

2. Nhập một ID duy nhất cho nhà cung cấp.

   ```bash
   $ /connect

   ┌  Add credential
   │
   ◇  Enter provider id
   │  myprovider
   └
   ```

   :::note
   Hãy chọn một ID dễ nhớ, bạn sẽ dùng nó trong tệp cấu hình.
   :::

3. Nhập khóa API của nhà cung cấp.

   ```bash
   $ /connect

   ┌  Add credential
   │
   ▲  This only stores a credential for myprovider - you will need to configure it in opencode.json, check the docs for examples.
   │
   ◇  Enter your API key
   │  sk-...
   └
   ```

4. Tạo hoặc cập nhật tệp `opencode.json` trong thư mục dự án của bạn:

   ```json title="opencode.json" ""myprovider"" {5-15}
   {
     "$schema": "https://opencode.ai/config.json",
     "provider": {
       "myprovider": {
         "npm": "@ai-sdk/openai-compatible",
         "name": "My AI Provider Display Name",
         "options": {
           "baseURL": "https://api.myprovider.com/v1"
         },
         "models": {
           "my-model-name": {
             "name": "My Model Display Name"
           }
         }
       }
     }
   }
   ```

   Đây là các tùy chọn cấu hình:
   - **npm**: package AI SDK cần dùng, `@ai-sdk/openai-compatible` cho các nhà cung cấp tương thích OpenAI (cho `/v1/chat/completions`). Nếu nhà cung cấp/mô hình của bạn dùng `/v1/responses`, hãy dùng `@ai-sdk/openai`.
   - **name**: Tên hiển thị trong UI.
   - **models**: Các mô hình khả dụng.
   - **options.baseURL**: URL của API endpoint.
   - **options.apiKey**: Tùy chọn đặt khóa API, nếu không dùng xác thực.
   - **options.headers**: Tùy chọn đặt header tùy chỉnh.

   Xem thêm các tùy chọn nâng cao trong ví dụ bên dưới.

5. Chạy lệnh `/models`, nhà cung cấp và các mô hình tùy chỉnh của bạn sẽ xuất hiện trong danh sách chọn.

---

##### Ví dụ

Dưới đây là ví dụ đặt các tùy chọn `apiKey`, `headers` và `limit` cho mô hình.

```json title="opencode.json" {9,11,17-20}
{
  "$schema": "https://opencode.ai/config.json",
  "provider": {
    "myprovider": {
      "npm": "@ai-sdk/openai-compatible",
      "name": "My AI Provider Display Name",
      "options": {
        "baseURL": "https://api.myprovider.com/v1",
        "apiKey": "{env:ANTHROPIC_API_KEY}",
        "headers": {
          "Authorization": "Bearer custom-token"
        }
      },
      "models": {
        "my-model-name": {
          "name": "My Model Display Name",
          "limit": {
            "context": 200000,
            "output": 65536
          }
        }
      }
    }
  }
}
```

Chi tiết cấu hình:

- **apiKey**: Đặt bằng cú pháp biến `env`, [tìm hiểu thêm](/docs/config#env-vars).
- **headers**: Header tùy chỉnh được gửi kèm mỗi yêu cầu.
- **limit.context**: Số token đầu vào tối đa mà mô hình chấp nhận.
- **limit.output**: Số token tối đa mà mô hình có thể tạo ra.

Các trường `limit` giúp OpenCode hiểu bạn còn bao nhiêu ngữ cảnh. Các nhà cung cấp tiêu chuẩn tự động lấy những giá trị này từ models.dev.

## Khắc phục sự cố

Nếu bạn gặp khó khăn khi cấu hình một nhà cung cấp, hãy kiểm tra những điều sau:

1. **Kiểm tra thiết lập xác thực**: Chạy `opencode auth list` để xem thông tin đăng nhập
   của nhà cung cấp đã được thêm vào cấu hình của bạn chưa.

   Điều này không áp dụng với các nhà cung cấp như Amazon Bedrock, vì chúng dựa vào biến môi trường để xác thực.

2. Với các nhà cung cấp tùy chỉnh, hãy kiểm tra cấu hình opencode và:
   - Đảm bảo ID nhà cung cấp dùng trong lệnh `/connect` khớp với ID trong cấu hình opencode của bạn.
   - Đảm bảo package npm đúng được dùng cho nhà cung cấp đó. Ví dụ, dùng `@ai-sdk/cerebras` cho Cerebras. Với mọi nhà cung cấp tương thích OpenAI khác, hãy dùng `@ai-sdk/openai-compatible` (cho `/v1/chat/completions`); nếu một mô hình dùng `/v1/responses`, hãy dùng `@ai-sdk/openai`. Với cấu hình hỗn hợp dưới một nhà cung cấp, bạn có thể ghi đè cho từng mô hình qua `provider.npm`.
   - Kiểm tra API endpoint đúng được dùng trong trường `options.baseURL`.
